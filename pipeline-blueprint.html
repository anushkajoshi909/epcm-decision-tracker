Meeting Protocol → Warning

The full request path through the EPCM Decision & Interface Action Tracker, drawn so the boundary between LLM interpretation and deterministic Python is the first thing a reader sees — not a detail buried in prose.

Semantic — LLM
Deterministic — Python rules
Orchestration & data — n8n / FastAPI / JSON
The one rule the whole architecture follows

Use the LLM only where a sentence has to be read and interpreted — what was decided, who's named, which discipline. The moment a question has one correct answer regardless of phrasing — is owner null? is this date before today? — it becomes a deterministic check in rules.py: reproducible, unit-testable, and free to run.

Step-by-step reference

StepTypeWhat happensWhy here, not elsewhere
n8n Webhook Orchestration Receives the POST containing the protocol text. Entry point — any real system (SharePoint, a form, a schedule) can call it.
FastAPI Orchestration Validates the request, wires the rest of the pipeline together. One typed REST contract in and out — n8n never needs to know Python.
LLM Extraction Semantic — LLM Reads free text, extracts decisions, actions, owner, deadline, discipline. The only step that actually requires understanding language.
Pydantic Validate Contract Checks the LLM's JSON against the LLMExtraction schema; one controlled retry on failure. Guarantees a fixed shape even though LLM content varies call to call.
Rules Engine Deterministic Flags missing owner/deadline, overdue dates, unresolved dependencies, closed deliverables. Every check has one right answer — asking an LLM would only add cost and variance.
JSON Response Orchestration Returns decisions, actions, issues, requires_attention. Same typed contract n8n started with — nothing implicit to parse.
n8n: IF Orchestration Branches purely on the requires_attention boolean. Routes a fact FastAPI already computed — decides nothing itself.
Notify (Discord) Orchestration Posts the formatted warning to a channel when the branch is true. Swapping this for Teams/email/a ticket is a node change, not a code change.

Say this out loud (≈2 min)

I wanted to understand the kind of practical AI automation used in EPCM, so I built a small adjacent use case rather than copying an existing prototype. My workflow analyses project meeting protocols and extracts decisions, actions, owners, deadlines and affected deliverables.

A meeting protocol enters through an n8n webhook, n8n calls a Python FastAPI service through REST, the LLM performs structured semantic extraction using Pydantic, deterministic Python rules identify things like missing owners or unresolved dependencies, and n8n handles the downstream warning workflow.

I also created a small evaluation dataset to test the structured extraction and issue detection.
